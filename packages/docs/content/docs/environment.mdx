# Environment Variables

ShipChamber reads these environment variables at startup. For startup services, `shipchamber startup enable` snapshots the current environment by default, so rerun it after changing variables you want the service to use.

## ShipChamber server

### `SHIPCHAMBER_HOST`

Bind address for the ShipChamber web server. Use `0.0.0.0` to allow access from other machines.

### `SHIPCHAMBER_UI_PASSWORD`

Password for the browser UI. Use this when binding outside localhost, using tunnels, or running behind a reverse proxy.

### `SHIPCHAMBER_API_ONLY`

Starts ShipChamber in headless mode when set to `true` or `1`. API routes stay available for desktop and mobile clients, but the browser UI is not served.

### `SHIPCHAMBER_DATA_DIR`

Overrides the ShipChamber data directory. The default is `~/.config/shipchamber`.

### `SHIPCHAMBER_CHATS_DIR`

Moves the managed chat directories that ShipChamber creates for chats without a project. The default is `~/.config/shipchamber/chats`. Set it to a directory the OpenCode server can read when ShipChamber and OpenCode run as different users. Existing chats are not moved.

### `SHIPCHAMBER_COMPRESS_API`

Controls API response compression. Use `true` or `1` to force it on, `false` or `0` to force it off.

### `SHIPCHAMBER_SKIP_API_COMPRESSION`

Disables API response compression when set to `true` or `1`. This takes precedence over `SHIPCHAMBER_COMPRESS_API`.

### `SHIPCHAMBER_VERBOSE_REQUEST_LOGS`

Enables verbose HTTP request logs when set to `true` or `1`.

### `SHIPCHAMBER_UPDATE_API_URL`

Overrides the update-check API endpoint. Most users should leave this unset.

### `SHIPCHAMBER_PACKAGE_MANAGER`

Forces the package manager used by update operations when auto-detection is wrong.

## OpenCode server

### `OPENCODE_HOST`

Connects ShipChamber to an existing OpenCode server. The value must be an `http` or `https` origin with an explicit port and no path, query, or hash. `OPENCODE_HOST` takes precedence over `OPENCODE_PORT`.

### `OPENCODE_PORT`

Sets the OpenCode server port. With managed OpenCode this requests the managed port; with `OPENCODE_SKIP_START=true` it connects to an external server on that port.

### `OPENCODE_SKIP_START`

Prevents ShipChamber from starting its own OpenCode server when set to `true`.

### `SHIPCHAMBER_OPENCODE_HOSTNAME`

Bind hostname for the OpenCode server managed by ShipChamber. The default is `127.0.0.1`.

### `OPENCODE_BINARY`

Path to the `opencode` executable ShipChamber should run.

### `OPENCODE_CONFIG`

Path to a specific OpenCode config file.

### `OPENCODE_CONFIG_DIR`

Path to a specific OpenCode config directory for agents, skills, snippets, and config discovery.

### `OPENCODE_DATA_DIR`

Custom data directory for the managed OpenCode server.

### `OPENCODE_WSL_DISTRO`

Selects the WSL distro used for OpenCode integration on Windows.

### `SHIPCHAMBER_OPENCODE_WSL_DISTRO`

ShipChamber-specific alias for selecting the WSL distro. `OPENCODE_WSL_DISTRO` takes precedence when both are set.

### `OPENCODE_JWT_SECRET`

Secret used to sign UI authentication tokens. Use a long random value for persistent service deployments.

## Terminal and Git

### `SHIPCHAMBER_TERMINAL_SHELL`

Shell executable used for ShipChamber terminal sessions.

### `SHIPCHAMBER_GIT_BINARY`

Git executable used by ShipChamber Git features.

### `GIT_BINARY`

Alternative Git executable override. Prefer `SHIPCHAMBER_GIT_BINARY` for ShipChamber-specific configuration.

### `SHIPCHAMBER_GIT_READ_CACHE_TTL_MS`

Time-to-live, in milliseconds, for cached Git-backed file reads. Set `0` to disable this cache while debugging.

## Voice and tunnels

### `OPENAI_API_KEY`

API key used by ShipChamber voice features that call OpenAI-compatible services.

### `SHIPCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Allows remote OpenAI-compatible base URLs for voice features when set to `true` or `1`.

### `NGROK_AUTHTOKEN`

ngrok auth token used by ShipChamber tunnel commands. You can also configure ngrok with `ngrok config add-authtoken <token>`.

## Runtime helpers

### `BUN_BINARY`

Bun executable ShipChamber should use when spawning daemon processes.

### `BUN_INSTALL`

Bun installation root. ShipChamber uses it to find `bin/bun` for daemon startup and updates.

### `VITE_OPENCODE_URL`

Build-time API base URL for the Vite-built web app. Most users should not set it for normal CLI or desktop usage.
